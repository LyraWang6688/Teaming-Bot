# 妙记所有者任务链路验收

日期：2026-09-22。范围：用户确认的“先入任务、再检查 ABC、再确认妙记所有者”，以及重复事件处理、恢复入口和日志凭据泄露修复。

## 实现

- 复用 meeting_pipeline_tasks 和两个现有唯一索引；线上 status 是 text，无额外枚举/check 约束，新增 skipped/blocked 不需要 DDL。
- 事件入口仅校验、入队；即使没有 ABC 也有任务记录。正常跳过结果不创建新的 meeting_records 或交付任务，既有历史记录不删除不重写。
- 标题合格后才查询妙记；分享权限不赋予分析资格。owner_id 与同应用当前授权 open_id 比较，只有本人且有效初始化才继续。
- minute_read_forbidden -> blocked/info；minute_not_owner 与标题不符 -> skipped/info；临时错误 -> scheduled，最多 3 次尝试；未知所有者不冒充非所有者。
- 插入使用 ON CONFLICT DO NOTHING，重复事件不能清锁或重置终态。不同录制 token 不静默替换同会议任务。
- 启动恢复不直接执行任务，统一由 worker 原子领取到期/过期锁任务。修正原始 SQL 返回 snake_case 被当作 camelCase 的读取问题。
- 移除绕过资格判断的文字稿恢复捷径，正常路径在资格通过后复用数据库文字稿；两条交付链路继续独立执行。
- 安全修复覆盖 6 处 SDK 构造：用户客户端、Base 客户端、应用配置、登录回调、长连接及事件分发器。SDK 原始字符串和错误对象不进入控制台；业务包装层继续提供脱敏诊断。

## 已验证

- 17 项隔离测试通过：非 ABC 不访问妙记；分享后非所有者跳过；无权限 blocked；所有者及初始化判断；临时重试及上限；缺失身份 fail-closed；并发重复入队；参会人/所有者任务隔离；重复不改锁和终态；事件先入队；跳过不触发报告/交付；启动恢复不绕过 worker；本地运行保护。
- SDK 漏洞触发替代测试：嵌套 Axios 错误、Authorization 请求头、错误消息、原始字符串、循环引用均携带哨兵密钥，输出中无哨兵；正常数字错误码保留，非请求 SDK 异常仍有诊断。
- TypeScript、ESLint、git diff --check 通过（部署前最终复核）。
- Supabase 临时表事务验证通过：复制现有表与索引，重复插入不新增；pending 与过期 running 可领取；skipped/blocked、未来 scheduled、新鲜 running 不领取。事务回滚，不触碰生产业务行。此测试不等于跨连接并发故障注入。

## 仍需真实会议验收

本次不主动新建会议、调用模型或重发历史消息。上线后用真实新会议分别验证：所有者正常分析；已分享的参会人跳过；未分享的参会人 blocked；没有 ABC 跳过。检查所有者唯一报告、通知接收人和 Base 内容。不能把隔离测试宣称为这些外部行为全部通过。

## 恢复与边界

blocked 不自动重试，避免重复投递不断刷请求。管理员修复授权后，先核实 task_id、integration_id、minute_token、原 reasonCode，确认没有运行租约、没有已完成报告，再在事务中限定 status='blocked' 恢复 pending、清除完成时间和旧错误、重置尝试次数，并写 meeting.pipeline.manual_resume 审计（含操作者、原原因、任务与集成 ID）。目前没有新增前端恢复按钮。正常 skipped 和 completed 不批量重置。

现有 20 分钟锁超时机制仍保留；未实现任意长任务的租约心跳/fencing，也未验证任意崩溃点的严格 exactly-once。每集成每会议一个任务的模型保留，多段录制需另行设计。

历史日志里的凭据副本不会因代码修复而消失。本次不擅自撤销用户授权或删除历史日志，既有泄露凭据须按实际有效状态另行处置。
