# 飞书集成三项功能完善实施计划

## 概述

在「组队会议动力分析」项目上完善三个功能：
1. **触发门槛改造**：飞书妙记事件触发分析时，门槛判断从「会议主持人 host_user」改为「会议创建人 organizer」，只有当创建人是已完成初始化配置的人时，会议才进入分析链路。
2. **多维表格数据源调整**：同步到飞书 Base 的数据，来源改为 Supabase `meeting_records` 表，Base 降级为协作展示镜像，Supabase 成为数据真相源。
3. **分析模板整体替换**：从 `/Users/wangying/Downloads/projects3` 迁移新版分析引擎、提示词、Schema 与前端报告组件，整体替换现有模板。

## 实施方案

### 功能1：触发门槛从 host 改为 organizer

#### 1.1 扩展 MeetingDetails 类型与获取逻辑
**文件**：`src/lib/feishu/meetings/meetingDetailsTypes.ts`
- 新增字段 `organizerOpenId?: string | null`（会议创建人 open_id）。
- 保留 `hostOpenId`（主持人仍需展示，但不作为门槛依据）。

**文件**：`src/lib/feishu/meetings/meetingDetailsService.ts`
- `fetchMeetingDetails` 在调用 VC API 后，增加获取 organizer 的逻辑：
  - 方案A（优先）：从妙记事件 payload 提取 `organizer` 字段（若飞书妙记事件自带）。
  - 方案B（fallback）：用会议详情中的 `calendar_id` + `event_id` 调用飞书 Calendar API `GET /v1/calendars/{calendar_id}/events/{event_id}`，从 `organizer` 字段提取 open_id。
  - 方案C（兜底）：若以上均不可得，`organizerOpenId = null`，门槛判定为「未解析创建人」直接跳过。
- 新增导出函数 `fetchMeetingOrganizer(integration, meetingId, calendarEventId?)` 封装 Calendar API 调用，复用 `callFeishuIntegrationUserOpenApi`。
- 错误映射：Calendar API 403/404 归类为 `organizer_unavailable`，不阻断流程，仅记日志。

#### 1.2 事件 payload 解析增强
**文件**：`src/lib/feishu/pipeline/meetingPipelineProcessor.ts`
- 在 `enqueueFeishuEvent` 解析妙记事件 payload 时，提取 `calendar_id`、`event_id`（若存在），存入 `MinuteGeneratedSource`。
- `MinuteGeneratedSource` 类型新增可选字段 `calendarEventId?: string`、`calendarId?: string`。

#### 1.3 门槛判断改用 organizer
**文件**：`src/lib/feishu/pipeline/meetingPipelineProcessor.ts` 的 `resolveMeetingAnalysisGate`（L221-L272）
- 将 `hostOpenId` 替换为 `organizerOpenId` 作为门槛匹配字段：
  - `meetingDetails?.organizerOpenId` 为空 → `reasonCode: 'meeting_organizer_unresolved'`
  - `findActiveInitializedIntegrationByAuthorizedOpenId({ authorizedOpenId: organizerOpenId })` 无匹配 → `reasonCode: 'meeting_organizer_not_initialized'`
  - 匹配到但 `integrationId !== context.integration.id` → `reasonCode: 'meeting_organizer_owned_by_other_integration'`
- `MeetingAnalysisGateResult` 类型字段名从 `hostOpenId` 改为 `organizerOpenId`。
- 审计日志 `writeMeetingAnalysisGateAudit` 同步更新字段名与文案。

#### 1.4 持久化 organizer
**文件**：`src/lib/reports/meetingReportStore.ts`
- `meetingDetailsFields` 增加写入 `organizerOpenId`。
- `meeting_records` 表若没有 `organizerOpenId` 列，需在 `src/lib/db/schema.ts` 增加该字段并生成迁移。

**文件**：`src/lib/db/schema.ts`
- `meetingRecords` 表增加 `organizerOpenId text` 列（可空）。

#### 1.5 文档同步
- 更新 `docs/飞书集成设计.md` 第 7 章初始化门槛说明，从「主持人」改为「会议创建人」。
- 更新 `docs/后台分析逻辑说明.md` 第 2、8、12 章涉及门槛判断的描述。

### 功能2：多维表格数据源改为 Supabase

#### 2.1 读取路径改造（Base → Supabase）
**文件**：`src/app/api/feishu/record/route.ts`
- 移除 `getBitableRecord` 调用分支（L81-L114）。
- 统一从 `meeting_records` 表读取：优先 `getMeetingRecordByIntegrationAndMeeting`，fallback `getMeetingRecordByLegacyReference`（按 baseRecordId）。
- 返回结构保持不变（前端契约稳定），数据来源切换为 Supabase。

**文件**：`src/lib/feishu/bitable/bitableOpenApi.ts`
- `findMeetingRecordByMeetingId` 与 `getBitableRecord` 标记为「仅用于 Base 写回前查找记录」，不再用于业务读取。
- 新增 `getMeetingRecordFromSupabase(integrationId, meetingId)` 作为统一读取入口（实际复用 `meetingReportStore` 的函数，避免重复）。

#### 2.2 写入路径改造（先 Supabase，后同步 Base）
**文件**：`src/lib/feishu/pipeline/meetingPipelineProcessor.ts`
- 分析完成后，调用顺序调整为：
  1. `persistMeetingReport`（写 Supabase `meeting_records.analysisResult / reportUrl`）—— 真相源
  2. `upsertMeetingWaitingRecord` / `updateMeetingRecordFields`（写 Base）—— 同步镜像，字段值从 Supabase 记录读取后写入
- `setMeetingProcessStatus` 的状态值仍写 Base，但状态来源以 Supabase `meeting_records.status` 为准。
- 新增辅助函数 `syncMeetingRecordToBase(integration, supabaseRecord)`：从 Supabase 记录构造 Base 字段值并写入，集中管理「Supabase → Base」同步逻辑。

#### 2.3 Base 字段构造改用 Supabase 数据
**文件**：`src/lib/feishu/pipeline/meetingPipelineProcessor.ts` 的 `buildMeetingBaseFields`
- `创建人` 字段改为从 `meeting_records.organizerOpenId` 读取（而非 `authorization.authorizedOpenId`）。
- `会议名称` 仍从 `meetingDetails.topic` 读取。

#### 2.4 文档同步

## 假设与决策

1. **organizer 获取优先级**：妙记事件 payload > Calendar API > 兜底为空跳过。实现时需先检查飞书妙记事件实际 payload 字段，确认是否自带 organizer。
2. **Base 不废弃**：仍作为飞书协作展示层，写入保持，但数据真相在 Supabase。
3. **模板迁移为整体覆盖**：projects3 的 analysis 目录整体迁移，不保留旧引擎混用。
4. **类型兼容**：新 `AnalysisResult` 若与现有飞书集成字段冲突，以新模板为准，调整集成层适配。
5. **projects3 文件读取**：Glob 工具对该目录有权限限制，迁移阶段需用 Read 逐个确认文件内容后复制。
