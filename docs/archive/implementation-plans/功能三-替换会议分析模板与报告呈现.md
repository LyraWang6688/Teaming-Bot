# 功能三：替换会议分析模板与报告呈现

## Context

当前项目「组队会议动力分析」的会议分析逻辑（V1：四色标行为评估 + 决策树 Zone 判定）和报告呈现（V1 Dashboard）需要替换为 `projects3` 项目的版本（V2：证据一次提取+报告写作并行 + psychologicalSafety/accountability 两维方向 + 分页 PDF 报告）。

**用户核心诉求**：
- 已生成的报告，仍用生成时的模板渲染（数据快照永久保存，渲染器版本化路由）
- 新创建的会议报告用新模板
- 飞书集成、pipeline、Supabase、Base 同步、OAuth、事件订阅等**全部保留不变**

**迁移范围**：仅「分析逻辑」+「报告呈现」。pipeline 调用分析、持久化、报告页路由等接口边界保持不变。

## 迁移策略：版本化渲染器路由

利用已有的 `analysisSchemaVersion` 字段（当前=1，bump 到 2）做渲染器路由：
- 旧报告（schemaVersion=1）→ V1 渲染器（`AnalysisDashboardV1`，冻结不动）
- 新报告（schemaVersion=2）→ V2 渲染器（`AnalysisDashboardV2`，projects3 版本）

数据层：V1/V2 类型并存，`AnalysisResult` 默认指 V2。旧报告 JSONB 仍是 V1 结构，由 V1 渲染器按 V1 类型读取。

## 风险与注意事项

1. **V1 渲染器冻结**：`AnalysisDashboardV1.tsx` 及 V1 charts 重命名后**不再修改**，只用于读旧数据。未来 V3 迭代时同理保留 V2 冻结。
2. **provider env 兼容**：projects3 `provider.ts` 默认读 `LLM_API_KEY`/`LLM_BASE_URL`，需改成 fallback 到 `DOUBAO_API_KEY`/`DOUBAO_BASE_URL`/`ARK_API_KEY`/`ARK_BASE_URL`，避免用户在服务器配新 env。
3. **模型一致性**：projects3 默认模型 `doubao-seed-2-0-pro-260215`，与当前项目一致，无需改模型配置。
4. **旧报告 schemaVersion 缺失值**：极早期报告可能 `analysisSchemaVersion` 为 null，路由时 `null` 或 `undefined` 当作 V1 处理。
5. **死代码删除**：`BehaviorRadar`/`CommunicationBubbleChart`/`teamingRules.ts`/`markdownFormatter.ts` 删除前再次 grep 确认无引用。
