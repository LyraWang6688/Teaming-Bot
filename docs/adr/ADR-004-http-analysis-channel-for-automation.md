# ADR-004: 为自动化补一条 HTTP 分析通道——宿主取数，服务器分析

- **状态**：Proposed
- **日期**：2026-10-15
- **类别**：接入通道 / 产品形态
- **取代**：无。**与 ADR-003 并存**：ADR-003 定的分工（宿主取数、只做分析的那一端不碰飞书）完全不变；本文补上 ADR-003 形态**覆盖不到的宿主环境**。

---

## Context

ADR-003 定下分工：**宿主取数，分析端只做分析**。这条分工已在【普通对话】里端到端验证通过（2026-10-14）。

但产品的目标是**自动**：妙记生成后自己分析、自己推送。实测发现这条路在 stdio MCP 形态下**被宿主环境堵死**。

### 事实一：豆包工作的定时任务环境不暴露 MCP 连接器工具

`[Host]` 同一台机器、同一个连接器、同一个账号，四组观察：

| 场景 | MCP 工具可用 | 证据 |
|---|---|---|
| 普通对话（00:07~00:14） | ✅ | `teaming_analyze_transcript` 调用成功；报告页 HTTP 200；卡片发出 |
| 定时任务（00:45） | ❌ | 宿主原文：「工具搜索未命中；直接调用返回 `Tool not found or is not available`」 |
| 定时任务（00:55） | ❌ | 同上，「多次搜索均无命中」 |
| 普通对话（01:2x） | ✅ | `teaming_doctor` 返回 ready |

`[Repo]` **同期本机 MCP 诊断日志**（`~/.teaming-mcp/.state/mcp.log`）：

```
普通对话与定时任务的连接【都】出现  initialize → notifications/initialized → tools/list
【只有普通对话】之后出现 tools/call
```

**证据强度说明（不编造）**：

- 两次连接的 `cwd` 都是同一个 `…/DoubaoWork/Profile 3/sandbox_envs_dir/envs/…`，
  **因此 `cwd` 无法区分"定时任务"与"普通对话"**。
- 「16:45:34 那次连接来自定时任务」是**推断**（依据仅为时间与你点击"立即运行"吻合），
  **不是直接证据**。
- 本事实最硬的证据是**宿主自己报告的 `Tool not found`**，加上普通对话同一时刻可用所形成的对照。

### 事实二：MCP 只是 stdio 包装，不是唯一形态

`[Repo]` 分析引擎、报告渲染、服务器发布都在 `teaming-mcp` 包内，**但它们也都能在服务器上运行**——服务器已持有分析凭证（`HOST_ANALYSIS_*`，见 `.env.production`）与同一套引擎代码。

### 事实三：宿主在定时任务环境里**有**命令行/网络能力

`[Host]` 本轮定时任务的执行留痕显示它成功运行了：

```
lark-cli minutes +search --owner-ids me        → exit=0
lark-cli minutes +search --participant-ids me  → exit=0
lark-cli minutes +detail --transcript …        → exit=0（逐字稿已导出）
```

**它拿不到 MCP 工具，却拿得到命令行。** 这两条是不同的通道。

### 由此暴露的核心矛盾

「自动」依赖宿主调度（ADR-003 事实三），而**宿主调度恰好跑在拿不到 MCP 工具的环境里**。
把自动化绑死在 stdio MCP 上，等于**放弃自动**。

---

## Options Considered

### Option A：只保留 MCP，把"自动"降级为"手动触发"

- 成本最低：什么都不用改。
- 但这等于放弃产品目标（事件驱动）。
- **✗ 否决**：用户要的是"开完会自动收到报告"，不是"记得去说一句"。

### Option B：MCP 换远程传输（HTTP / SSE transport）

- MCP 协议确实支持远程传输，理论上可绕开 stdio。
- 但**仍然要求宿主把它当 MCP 工具**——而定时任务环境恰恰**不暴露任何 MCP 工具**（事实一）。
- 且豆包工作是否支持该 transport **未确认**。
- **✗ 否决**：没有解决真正的瓶颈。

### Option C：给服务器加一条 HTTP 分析接口，宿主用命令行/网络调用 ★选中

- 走**命令行/网络**通道，**不经过宿主的工具集**。
- 宿主显然具备该能力（事实三：它在定时任务里成功跑了 lark-cli）。
- 顺带解决三件事：新用户零安装、Windows 无需折腾 node/npm、任何宿主都能接。
- 复用同一套分析引擎与报告页。

### Option D：放弃豆包账号，只服务有飞书应用的账号

- 与 ADR-003 的结论直接冲突（豆包账号恰恰是不能建应用的）。
- **✗ 否决**。

---

## Decision

**增加服务器接口 `POST /api/host/v1/analyze`，作为「自动化通道」。**

MCP **继续保留**，作为「交互式通道」。两条通道并存，分工不变（ADR-003）：

| | 交互式通道 | 自动化通道 |
|---|---|---|
| 形态 | stdio MCP | HTTP |
| 用在 | 普通对话里让 AI 分析一场会 | 宿主的定时任务 / 任何拿不到 MCP 工具的宿主 |
| 分析在哪 | **宿主本机**（逐字稿不出本机） | **服务器**（逐字稿随请求上传） |
| 取数与投递 | 宿主自带飞书能力 | 宿主自带飞书能力（**不变**） |

**两条通道必须共用**：同一套分析引擎、同一个报告页、同一套接入码凭证（`host_credentials`）、同一套幂等键（逐字稿内容哈希）。

---

## Why

1. **瓶颈是宿主限制，不是我们的实现。** 定时任务不暴露 MCP 工具，这一点我们改不了；能改的是我们提供什么通道。
2. **HTTP 不经过工具集。** 这是它绕开限制的机制——不是"HTTP 比 MCP 好"，而是它走的是另一条路。
3. **它与 ADR-003 的分工完全一致。** 变的只是"分析在哪台机器执行"，"谁取数、谁投递"一个字没改。
4. **它把安装成本降到零。** 这对"要发给别人用"的产品目标很关键（MCP 需要 node + npm + 配连接器）。

---

## Consequences

### Positive

- **「自动」成立**：宿主定时任务 → 取逐字稿 → HTTP 调用 → 报告页 → 宿主用自带飞书能力推卡片。
- **新用户零安装**：不用 node、不用 npm、不用配连接器。
- **跨平台无差异**：Windows 与 macOS 走同一条路。
- **覆盖所有宿主**：只要它能发 HTTP（几乎都能）。

### Trade-offs

| 代价 | 说明 | 缓解 |
|---|---|---|
| **逐字稿要上传服务器** | MCP 模式是本地分析，逐字稿不出本机 | 报告与逐字稿**本来就已经上传**（`/api/host/v1/reports` 会调 `updateMeetingRecordTranscript`）；但**必须在接入文档里明确告知用户**这一点差异 |
| **模型费用从"用户本地 key"变成"服务器承担"** | 成本结构变化 | 按接入码 / `integrationId` 记账；幂等（内容哈希）避免重复消耗 |
| **服务器多一个对外接口** | 攻击面增加 | 沿用 host token 认证（SHA-256 哈希比对 + `timingSafeEqual`）+ 限流 + nginx 白名单；**接入码的限流是已知待办** |

### Future Constraints

- **两条通道的行为必须一致。** 同一份逐字稿在 MCP 与 HTTP 上必须得到同一个报告（同一引擎、同一幂等键）。新增能力时要明确：给哪条通道，还是两条都给。
- **新增路由必须同步 nginx 白名单**（`/etc/nginx/snippets/allowlist-meeting.conf`）。今天已踩过这个坑：漏加时外部访问返回 **HTTP 000**，容器内却是 401，排查成本很高。
- **不要在 HTTP 通道里重新实现分析逻辑**，必须复用引擎，否则两条路会漂移。

## Evidence

`[Host]` **普通对话可用**（豆包工作，2026-10-15 01:2x）：

```
找到了 teaming_doctor（teaming 会议分析服务的环境体检工具），现在执行。
体检完成：状态 ✅ ready；lark-cli 1.0.97；分析引擎路径存在、构建正常；问题列表：无
```

`[Host]` **定时任务不可用**（同一账号、同一连接器，2026-10-15 00:55）：

```
工具搜索仍未发现 teaming 工具。
再次尝试调用 teaming_analyze_transcript → 工具仍不可用。
记录本轮处理状态（analysis_blocked_mcp_unavailable，可重试），然后如实汇报。
```

`[Repo]` **MCP 诊断日志**：普通对话出现 `tools/call`；定时任务侧只到 `tools/list`。
