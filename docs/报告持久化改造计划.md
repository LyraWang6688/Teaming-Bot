# 报告持久化改造计划

> 状态：待实施  
> 开发分支：`codex/persist-meeting-reports`  
> 基线：`origin/main` / `323ee41`  
> 计划日期：2026-07-22

## 一、目标

将会议报告的长期事实来源从飞书多维表格调整为 Supabase：

```text
Supabase：完整报告的长期事实来源
飞书 Base：组织协作入口、状态、摘要和报告链接
飞书应用：新会议监听、妙记读取和 Base 同步
```

改造完成后，删除飞书应用、OAuth 失效、Base 权限变化或 Docker 容器重建，都不应影响已经完成的历史报告。数据库、服务器或域名迁移时，只要同步迁移数据库、环境配置和域名跳转规则，原报告公开 ID 可以保持不变。

## 二、本次范围

本次实现：

- 将完整 `AnalysisResult` 保存到 `meeting_records`。
- 为每份报告分配唯一且不可变的 `report_public_id`。
- 新增 `/report/[reportPublicId]` 永久报告页。
- 调整飞书会议管线为“先保存报告，再同步 Base”。
- 保留现有 `/report?recordId=...` 链路，兼容历史链接。
- 提供已有 Base 报告的可重复回填能力。
- 增加报告保存、读取、Base 同步与回填日志。

本次不实现：

- 不修改 AI 分析规则、提示词或 `AnalysisResult` 业务结构。
- 不把会议文字稿迁入 `meeting_records`；本阶段只持久化渲染报告所需的数据。
- 不立即删除旧报告页面和 `/api/feishu/record`。
- 不在本功能分支中混入 Next.js / React 依赖升级。

## 三、数据库设计

在现有 `meeting_records` 表上进行向后兼容的增量修改：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `report_public_id` | `uuid` | 对外报告标识，随机、唯一、生成后不变 |
| `analysis_result` | `jsonb` | 完整 `AnalysisResult` |
| `analysis_schema_version` | `integer` | 报告 JSON 结构版本，首版为 `1` |
| `analysis_summary` | `text` | 分析摘要，便于列表与排障 |
| `completed_at` | `timestamptz` | 报告持久化完成时间 |

约束与安全规则：

- 使用 Supabase 版本化 migration 添加字段和唯一索引。
- 第一版新增字段允许兼容旧记录，不删除现有字段。
- 继续以 `(integration_id, feishu_meeting_id)` 保证业务幂等。
- `report_public_id` 使用数据库随机 UUID，并建立唯一索引。
- 删除飞书集成时不得级联删除会议报告。
- `meeting_records` 保持 RLS；不向 `anon`、`authenticated` 开放表级直接读取策略。
- 浏览器不直接连接 Supabase 读取报告，所有读取发生在服务端。
- 数据库只保存公开 ID，不把当前域名写死为报告事实字段。

预计修改：

- `src/lib/db/schema.ts`
- `supabase/migrations/<timestamp>_persist_meeting_reports.sql`

## 四、报告数据层

新增：

```text
src/lib/reports/meetingReportStore.ts
src/lib/reports/reportUrl.ts
```

职责：

- 按 `integrationId + feishuMeetingId` 幂等创建或更新报告。
- 数据库冲突更新时复用原有 `report_public_id`。
- 保存 `AnalysisResult`、标题、摘要、项目、组织和 Base 记录关联。
- 按 `report_public_id` 精确读取已完成报告。
- 使用 `PROJECT_PUBLIC_URL` 在运行时生成 `/report/<reportPublicId>` 链接。
- 禁止日志输出报告正文、Token、App Secret 等敏感内容。

## 五、会议处理管线调整

修改 `src/lib/feishu/pipeline/meetingPipelineProcessor.ts`。

现状：

```text
获取文字稿 -> AI 分析 -> 写 Base JSON -> 报告页实时读取 Base
```

目标：

```text
获取文字稿
-> 查询是否已有持久化报告
-> 必要时执行 AI 分析
-> 保存完整报告到 Supabase
-> 生成永久报告链接
-> 将摘要、JSON 和链接同步到 Base
-> 完成数据库任务
```

失败与重试规则：

- 报告数据库写入失败：任务失败并重试，Base 不得标记为完成。
- 报告已保存但 Base 写入失败：保留报告，仅重试 Base 同步。
- 任务重试前先查询 `meeting_records`；已有完整报告时禁止重复调用大模型。
- Base 仍保留 `JSON数据`，作为协作展示和迁移期兼容副本，但不再是报告页的唯一数据源。

## 六、永久报告页面

新增：

```text
src/app/report/[reportPublicId]/page.tsx
src/app/report/[reportPublicId]/loading.tsx
src/app/report/[reportPublicId]/not-found.tsx
src/components/reports/PersistentReportView.tsx
```

地址格式：

```text
https://meeting.bamamei.online/report/<report_public_id>
```

实现原则：

- 动态路由使用 Next.js Server Component 在服务端直接读取数据库。
- 不为该页面额外暴露可遍历的公开报告 JSON 列表接口。
- `PersistentReportView` 仅负责把服务端取得的数据交给现有 `AnalysisDashboard`，保留 PDF 导出等交互。
- 报告不存在、未完成或数据结构不合法时返回明确的 404/错误状态。
- 报告内容不使用共享公共缓存，避免会议分析被中间缓存长期保存。
- 公开 ID 相当于持有链接即可访问的凭证，不允许使用自增 ID，也不提供枚举入口。

## 七、旧链接兼容与历史回填

现有链接继续保留：

```text
/report?recordId=...&integrationId=...&orgTargetId=...
```

迁移期策略：

1. 新会议只生成新的永久报告链接。
2. 旧报告页继续通过飞书 Base 读取，避免历史链接立即失效。
3. 历史回填成功后更新 Base 中的报告链接。
4. 旧链接可在找到对应持久化报告后跳转到永久链接。
5. 等回填覆盖率和线上访问日志确认后，再单独规划删除旧读取链路。

计划新增 `scripts/backfillMeetingReports.mjs`，要求支持：

- `dry-run`：只扫描和校验，不写数据库或 Base。
- 按项目、组织或单条 Base 记录限定范围。
- 重复执行保持幂等，不产生重复报告。
- 输出扫描、成功、跳过、失败数量及非敏感错误摘要。
- 单条失败不终止整批任务。

飞书应用已经删除且 Base 无法访问的历史报告，无法自动回填；需要恢复访问，或先导出 Base 数据再人工导入。

## 八、日志与审计

新增或调整结构化事件：

```text
meeting_report_persist_started

meeting_report_persist_failed
meeting_report_reused
meeting_report_loaded
meeting_report_not_found
meeting_report_base_sync_started

```

日志至少包含：

- `userId`
- `integrationId`
- `meetingId`
- `reportPublicId`
- `projectId`
- `orgTargetId`
- `baseRecordId`
- 阶段、结果、耗时和稳定错误类型

日志不得包含完整报告 JSON、文字稿、Access Token、Refresh Token 或 App Secret。

## 九、实施顺序与回滚

实施顺序：

```text
添加数据库字段和索引
-> 部署双写代码
-> 用新会议验证永久链接
-> 验证飞书不可访问时历史报告仍可打开
-> dry-run 扫描历史 Base 报告
-> 分批回填并更新 Base 链接
-> 观察线上日志与失败率
-> 后续版本再移除旧读取链路
```

回滚原则：

- 数据库迁移仅增加字段，旧版本代码可以忽略这些字段。
- 双写期继续向 Base 写入完整 JSON，回滚应用代码后旧报告页仍可使用。
- 第一版不删除旧接口、旧页面和旧 Base 字段。
- 回滚时不删除已经持久化的 `meeting_records` 数据。
