## 一、目标与系统边界

本次改造统一完成四个目标：

1. 根据会议 ID 获取会议名称、主持人和会议时间等详情。
2. 精简飞书多维表格，将内部 JSON 和错误详情迁移到 Supabase。
3. 丰富飞书报告通知，面向用户展示会议名称和时间。
4. 将完整会议报告持久化到 Supabase，并生成不依赖飞书应用和 Base 的永久报告链接。

改造后的职责边界：

```text
Supabase
├─ 会议元数据
├─ 完整分析结果
├─ 报告公开 ID
├─ 任务状态
└─ 内部错误信息

飞书 Base
├─ 面向组织成员的会议信息
├─ 处理状态
├─ 文字稿和分析摘要
└─ 永久报告链接

飞书消息
├─ 会议名称
├─ 会议时间
└─ 查看报告按钮

飞书应用
├─ 新会议事件监听
├─ 会议详情和妙记读取
├─ Base 同步
└─ 报告完成通知
```

删除飞书应用、OAuth 失效、Base 权限变化或 Docker 容器重建，都不应影响已经完成的历史报告。数据库、服务器或域名迁移时，只要同步迁移数据库、环境配置和域名跳转规则，原报告公开 ID 可以保持不变。

## 二、改造前代码与目标之间的差距

改造前实现：

- 妙记生成事件提供会议 ID、minute token，并可能提供会议名称。
- 流水线没有主动查询飞书会议详情，因此没有可靠的主持人和会议时间。
- 完整 `AnalysisResult` 写入 Base 的 `JSON数据` 字段。
- 业务错误写入 Base 的 `错误信息` 字段。
- 现有报告页通过 `/api/feishu/record` 实时读取 Base 中的 `JSON数据`。
- 飞书报告消息只展示会议 ID。
- `meeting_records` 已有基础字段，但尚未成为报告数据的事实来源。

目标实现：

```text
妙记事件
-> 获取会议详情
-> 保存会议元数据
-> 获取文字稿
-> 执行或复用 AI 分析
-> 持久化完整报告
-> 生成永久报告链接
-> 同步精简后的 Base 字段
-> 发送丰富的飞书报告消息
```

## 三、会议详情接口

### 3.1 接口规范

使用飞书“获取会议详情”接口：

```text
GET /open-apis/vc/v1/meetings/:meeting_id
```

查询参数固定为：

```text
with_participants=false
with_meeting_ability=false
user_id_type=open_id
query_mode=0
```

调用身份：

- 使用当前集成数据库 TokenService 提供的 `user_access_token`。
- 不依赖 CLI Keychain。
- 不使用全局环境变量中的用户身份。
- 显式传入 `integration` 或 `integrationId`。

新增用户权限：

```text
vc:meeting.meetingevent:read
```

该权限必须同时加入：

- 一键创建应用的用户权限 addons。
- OAuth scope。
- 初始化权限校验。
- 飞书集成设计文档的权限清单。

接口限制：

- 只能查询归属于当前授权用户的会议。
- 只支持最近 90 天内的会议。
- 频率限制为 1000 次/分钟、50 次/秒。
- 403 `121005` 映射为内部“会议不属于当前授权用户或无权访问”错误。
- 404 `121004` 映射为内部“会议不存在或已超过可查询时间范围”错误。

### 3.2 数据映射

新增内部模型：

```ts
type MeetingDetails = {
  meetingId: string;
  topic: string | null;
  meetingUrl: string | null;
  status: 'calling' | 'ongoing' | 'ended' | 'unknown';
  createdAt: Date | null;
  startedAt: Date | null;
  endedAt: Date | null;
  hostOpenId: string | null;
  hostName: string | null;
  noteId: string | null;
};
```

字段来源：

| 内部字段 | 飞书响应字段 |
| --- | --- |
| `topic` | `meeting.topic` |
| `meetingUrl` | `meeting.url` |
| `status` | `meeting.status` |
| `createdAt` | `meeting.create_time` |
| `startedAt` | `meeting.start_time` |
| `endedAt` | `meeting.end_time` |
| `hostOpenId` | `meeting.host_user.id`，语义为主持人，不一定是预约组织者 |
| `noteId` | `meeting.note_id` |

明确不保存：

- 会议密码。
- 不用于业务展示的会议能力统计。
- 无必要的逐字稿或智能纪要文档 Token。

### 3.3 主持人语义与名称边界

会议详情接口的 `host_user` 表示主持人，不一定是预约组织者；接口只返回主持人 ID，不直接返回姓名。本次不为主持人姓名申请通讯录权限。

处理规则：

- `host_user.id` 使用 `open_id` 类型。
- 如果 `host_user.id` 等于当前 OAuth 授权人的 `authorized_open_id`，复用授权记录中的 `authorized_user_name` 作为主持人名称。
- 如果二者不相等，只保存 `hostOpenId` 用于内部关联，不向 Base、消息或报告展示原始 open_id。
- 产品字段暂用“主持人”；如果以后必须显示预约组织者，需要补充能明确返回组织者的接口。
- 主持人名称无法确认时不阻断会议分析和报告生成。

### 4.3 约束和安全

- 使用版本化 Supabase migration 添加字段和唯一索引。
- 新增字段第一版允许为空，兼容历史记录。
- 继续使用 `(integration_id, feishu_meeting_id)` 保证业务幂等。
- `report_public_id` 使用数据库随机 UUID，并建立唯一索引。
- 删除飞书集成时不得级联删除会议报告。
- `meeting_records` 保持 RLS。
- 不向 `anon`、`authenticated` 开放表级直接读取策略。
- 浏览器不直接连接 Supabase 读取报告。
- 公开报告只能通过服务端按 `report_public_id` 精确读取。
- 数据库不把当前域名作为永久事实；链接在运行时根据 `PROJECT_PUBLIC_URL` 生成。
- 日志不得输出完整报告、文字稿或令牌。

## 六、飞书 Base 字段调整

### 6.1 面向用户的目标字段

| 字段 | 内容 |
| --- | --- |
| `会议ID` | 保留为稳定业务关联键，是否在视图中隐藏由 Base 管理员决定 |
| `会议名称` | `meeting.topic` |
| `会议时间` | 优先使用开始时间，按产品时区格式化 |
| `主持人` | 仅在可由当前授权记录可靠匹配时展示姓名 |
| `处理状态` | 等待妙记、获取文字稿、分析中、已完成、失败 |
| `会议文字稿` | 妙记导出的文字稿 |
| `分析摘要` | `AnalysisResult.summary` |
| `报告链接` | `/report/<report_public_id>` 永久链接 |

### 6.2 从 Base 移除的字段

| 字段 | 新事实来源 |
| --- | --- |
| `JSON数据` | `meeting_records.analysis_result` |
| `错误信息` | `meeting_records.last_error_*` 和 `meeting_pipeline_tasks.last_error_*` |

代码调整：

- 新流水线停止写入 `JSON数据` 和 `错误信息`；`bitableOpenApi.ts` 在历史回填完成前暂时保留旧字段解析能力。
- `meetingPipelineProcessor.ts` 不再向 Base 写入这两个字段。
- 报告页面不再依赖 Base 的 `JSON数据`。
- 失败原因只进入数据库、结构化日志和审计日志。

### 6.3 字段删除顺序

不能先在 Base 中直接删除字段，否则旧代码写入会失败，历史报告也可能无法读取。

安全顺序：

```text
添加 Supabase 字段
-> 部署报告持久化和新报告读取链路
-> 新会议停止写 Base 的 JSON数据/错误信息
-> 回填历史 Base JSON 到 Supabase
-> 验证历史报告永久链接
-> 批量更新 Base 报告链接
-> dry-run 检查所有 active/archived 项目的 Base
-> 删除 JSON数据 和 错误信息 字段
```

计划新增一次性迁移脚本：

```text
scripts/migrateBaseUserFields.mjs
```

要求：

- 默认 `dry-run`。
- 按项目、组织或单张 Base 限定范围。
- 先按字段名读取字段 ID，再执行删除。
- 输出成功、跳过、失败数量。
- 单张 Base 失败不终止整批任务。
- 删除字段必须由管理员显式确认，不在应用启动时自动执行。

## 九、会议流水线调整

目标顺序：

```text
1. 收到 minutes.minute.generated_v1
2. 将事件幂等写入 meeting_pipeline_tasks
3. 获取或刷新会议详情
4. 将会议元数据写入 meeting_records
5. 创建或复用 Base 等待记录
6. 获取妙记文字稿
7. 查询是否已有持久化报告
8. 必要时执行 AI 分析
9. 保存完整报告到 Supabase
10. 生成永久报告链接
11. 将面向用户的字段同步到 Base
12. 完成数据库任务
13. 发送飞书报告消息
```

失败和重试：

- 会议详情接口 429、500 和网络错误：按任务状态重试。
- 会议详情 403/404：记录稳定错误类型；允许使用事件中已有会议名称继续处理，但人员和时间降级。
- 主持人姓名无法从当前授权身份可靠确认时：不阻断分析和报告，只省略主持人展示。
- 报告数据库写入失败：任务失败并重试，Base 不得标记为完成。
- 报告已保存但 Base 写入失败：保留报告，只重试 Base 同步。
- 任务重试前先查询 `meeting_records`；已有完整报告时禁止重复调用大模型。
- 同一会议的重复事件不得产生第二个 `report_public_id`。
- 飞书消息发送失败不回滚持久化报告和 Base 写入。

## 十、旧链接兼容与历史回填

现有链接：

```text
/report?recordId=...&integrationId=...&orgTargetId=...
```

迁移策略：

1. 新会议只生成新的永久报告链接。
2. 旧报告页在历史回填完成前继续读取 Base。
3. 历史回填将 Base 的 `JSON数据` 写入 Supabase。
4. 回填成功后更新 Base 中的报告链接。
5. 旧链接找到对应持久化报告后重定向到永久链接。
6. 所有相关 Base 完成回填后，才允许删除 `JSON数据` 和 `错误信息` 字段。
7. 等访问日志确认没有旧链路依赖后，再单独删除旧接口和旧页面。

计划新增：

```text
scripts/backfillMeetingReports.mjs
```

要求：

- 默认 `dry-run`。
- 按项目、组织或单条 Base 记录限定范围。
- 重复执行保持幂等。
- 输出扫描、成功、跳过、失败数量。
- 单条失败不终止整批任务。
- 无法访问的历史 Base 不伪造报告数据，需恢复访问或人工导入。

### 阶段 B：数据库和数据层

- 添加 Supabase migration。
- 实现会议记录与报告 Store。
- 验证幂等和 RLS。

### 阶段 C：新会议双链路

- 流水线获取会议详情。
- 报告写入 Supabase。
- 生成永久链接。
- Base 停止写 `JSON数据` 和 `错误信息`。
- 飞书通知使用丰富内容。

### 阶段 D：历史回填

- dry-run 扫描。
- 分项目、分组织回填。
- 更新历史报告链接。
- 验证飞书不可访问时报告仍可打开。

### 阶段 E：Base 字段删除

- 确认所有历史报告已回填。
- dry-run 获取各 Base 字段 ID。
- 管理员确认后删除 `JSON数据` 和 `错误信息`。
- 观察错误率和旧报告访问日志。

## 十六、回滚原则

- 数据库迁移第一阶段只增加字段，旧版本代码可忽略。
- 删除 Base 字段必须放在全部代码和历史数据迁移完成之后。
- 在字段正式删除前，可以回滚到旧 Base 读取链路。
- 报告已持久化但 Base 同步失败时，不删除 Supabase 报告。
- 回滚应用代码时不删除已生成的 `report_public_id` 和报告内容。
- 若会议详情接口暂时不可用，允许使用事件已有字段降级，不阻断已具备文字稿的会议分析。

## 十七、上线前仍需确认

1. 产品所说的“组织者”是否允许使用接口返回的主持人 `host_user`；如果不允许，需要补充预约组织者接口。
2. archived 项目的历史 Base 是否全部纳入第一批回填和字段删除。
3. 同一会议被同一组织内多个 integration 收到时，是组织内只分析一次，还是每个 integration 各自分析一次；该结论决定任务和报告唯一键是否改为 `org_target_id + feishu_meeting_id`。

已按当前产品决定固定的事项：

- 不读取、解析或展示参会人。
- `会议时间` 固定按 `Asia/Shanghai` 展示。
- Base 保留 `会议ID`，仅删除 `JSON数据` 和 `错误信息`。
