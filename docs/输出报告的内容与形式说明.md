## 1. 报告整体结构与版本路由

报告采用"版本化渲染器 + 结构化分析结果"的方式渲染：

| 层级 | 承载文件 | 作用 |
|------|---------|------|
| 路由层 | `src/components/reports/PersistentReportView.tsx` | 根据 `analysisSchemaVersion` 选择 V1 / V2 渲染器 |
| V2 模板 | `src/components/AnalysisDashboardV2.tsx` | 新报告的整体布局、姓名隐藏、PDF 导出 |
| V1 模板（冻结） | `src/components/AnalysisDashboardV1.tsx` | 旧报告按生成时模板渲染，不再修改 |
| V2 图表 | `src/components/charts/TeamStateChart.tsx`、`src/components/charts/NetworkGraph.tsx` | V2 状态四象限图与对话网络图 |
| V1 图表（冻结） | `src/components/charts/TeamStateChartV1.tsx`、`src/components/charts/NetworkGraphV1.tsx` | V1 旧图表，配合 V1 模板使用 |
| 动态数据 | `AnalysisResult`（默认指向 `AnalysisResultV2`） | 来自网页上传异步任务或飞书会议转写分析 |
| 飞书报告入口 | `/report/<reportPublicId>` | 服务端按随机公开 UUID 读取 `meeting_records.analysis_result`，并按 `analysis_schema_version` 路由 |
| 旧链接兼容入口 | `/report?recordId=xxx&integrationId=xxx&orgTargetId=xxx` | 优先查找已回填的数据库报告并跳转；API 响应包含 `analysisSchemaVersion` 供客户端路由 |

### 1.1 版本路由规则

```typescript
// PersistentReportView.tsx
const isV2 = (analysisSchemaVersion ?? 1) >= 2;
// isV2 ? AnalysisDashboardV2 : AnalysisDashboardV1
```

- 缺省 `analysisSchemaVersion` 视为 1，保证旧报告向前兼容；
- 飞书 `/api/feishu/record` API 响应中已新增 `analysisSchemaVersion` 字段；
- 网页上传链路写入的 `analysisSchemaVersion` 由 `MEETING_REPORT_SCHEMA_VERSION`（当前为 2）决定。

### 1.2 V2 报告四部分结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 报告开头                                                      │
│ 标题 + 理论基础 + 会议性质 + 人数 + 开启日期/时间 + 会议时长  │
│ + "AI 对会议的理解" + "AI 对本次会议预期产出的理解"           │
├──────────────────────────────────────────────────────────────┤
│ Part 1：团队学习是否正在发生？                                 │
│ 第一行：四象限图（左） + 整体区域判断（右）                    │
│ 第二行：心理安全感（左） + 高要求与责任承担（右）              │
│ 第三行：最值得抓住的团队学习契机                              │
├──────────────────────────────────────────────────────────────┤
│ Part 2：互动功能                                              │
│ 顶部：互动功能图例                                            │
│ 主体：网络图（左） + 两段总体观察（右）                       │
```

## 2. 报告开头

### 2.1 标题与理论基础

- 标题固定为"本次会议的团队学习状态评估与建议报告"；
- 只露出一次理论基础；
- 不再显示"一句话看本次会议"，正常报告也不在开头显示输入质量说明；
- 报告开头与 Part 1 共同位于第一页。

### 2.2 元信息

依次显示：

- 会议性质；
- 人数；
- 会议开启日期与时间；
- 会议时长。

### 2.3 并排说明

并排说明：

- "AI 对会议的理解"；
- "AI 对本次会议预期产出的理解"。

## 3. Part 1：团队学习是否正在发生？

### 3.1 主框架

- 主框架为心理安全感 × 高要求与责任承担；
- 横轴：高要求与责任承担，左低右高；
- 纵轴：心理安全感，下低上高，轴顶和轴底明确标示"高/低"，竖排文字保持正常阅读方向；
- 左上舒适区、右上学习区、左下冷漠区、右下焦虑区。

### 3.2 区域标签

- 区域标签固定使用"主区域""主区域，靠近相邻区域边界"，或在仅一个维度证据不足时使用"可能是 X 区或 Y 区"；
- 相邻或候选区域必须是四象限中真实共边的区域；
- 区域标签由代码生成，具体会议卡点放在解释正文，不得替代相邻区域；
- 两个维度都缺乏有效信号时暂不定位；仅一个维度拿不准时仍给出两个候选区域，并把图中定位点放在相应分界线上。

### 3.3 布局

- 第一行是四象限图（左）与整体区域判断（右）；
- 第二行是心理安全感（左）与高要求和责任承担（右）；
- 第三行整行呈现"最值得抓住的团队学习契机"。

### 3.4 引用框样式

- 固定字段不使用"证据"作为标题，原文片段由引用框的视觉样式自然表达。

## 4. Part 2：互动功能

### 4.1 成员节点

- 每位实质发言者都出现；
- 功能颜色固定为：推动=黄色、承接=蓝色、挑战=红色、观察=紫色、未明显观察到=灰色；
- 图上方显示四种互动功能图例，节点、成员卡片边框和功能标签使用同一套颜色；
- 节点内显示完整姓名和发言占比，圆圈大小表示发言占比；
- 英文姓名不截断；
- 同一种功能可以由多人发挥。

### 4.2 主要功能

- 主要功能由第一阶段逐项标注功能事件后汇总，报告写作阶段不得重新分配。

### 4.3 有向线

- 有向线表示承接、追问、挑战或回应，线宽表示频次；
- 箭头清晰表示回应方向；
- 语义图例分别解释圆圈大小、节点颜色、箭头和线宽，并避免统一使用蓝色造成误读；
- 有向线采用证据阶段锁定的语义互动，报告写作阶段只解释互动结构。

### 4.4 布局

- 图表与两段总体观察并排；
- 所有成员观察在图表下方使用两列卡片呈现，避免左侧空白、右侧过长。

### 4.5 成员卡片

- 成员卡片固定使用"主要发挥：X"和"发言占比：X%"；
- 代表性原文片段以"代表性片段"标示；
- 次要功能只自然融入文字，不机械追加固定短语。

## 5. Part 3：未完形与非共识

### 5.1 数量

每类 0–2 条。

### 5.2 未完形对话

未完形描述"对话的完成状态"，每条依次呈现：

- 主题；
- "对话走到了哪里"（`conversationSoFar`）；
- "尚未完成的是"（`whatRemains`）。

### 5.3 非共识

非共识描述"认知差异状态"，每条依次呈现：

- 主题；
- "不同关注"（`differentConcerns`）；
- "背后的共同目标"（`sharedGoal`）；
- "为什么值得被看见"（`whyItMatters`）。

### 5.4 判定原则

- 一个人提出挑战而其他人未回应，只能作为未完形，不能把沉默虚构成另一方立场；
- 同一主题只进入一个栏目；
- 普通会务、细小待办和已经充分整合的差异不进入 Part 3；
- 为空时明确说明未发现关键内容。

### 5.5 旧字段兼容

导入旧报告时：

- `whyUnfinished` 映射到 `conversationSoFar`；
- `whyNeedsClosure` 映射到 `whatRemains`；
- `whatEachSideSays` 映射到 `differentConcerns`；
- 前台只呈现新结构。

## 6. Part 4：领导者可以做什么？

### 6.1 数量

- 默认一条，特殊情况下最多两条。

### 6.2 Organizing to Learn 四行为

前台并列显示 Organizing to Learn 的四个领导行为并高亮本次建议对应项：

- 为学习框定情境（frame_for_learning）；
- 营造心理安全（create_psychological_safety）；
- 从失败中学习（learn_from_failure）；
- 跨越边界（cross_boundaries）。

### 6.3 建议字段

"建议做什么"（advice）只呈现一个有战略意义的高层动作，不塞入执行清单；再分别呈现：

- 为什么推荐（reasoning）；
- 合适时机（timing）；
- 如何验收 / 注意什么信号（signalToWatch）；
- 可选话术（optionalScript）。

### 6.4 表现良好的会议

表现良好的会议可以给保持与深化型建议。

## 7. 图表说明

### 7.1 TeamStateChart（V2）

**位置**：Part 1 第一行左栏

**输入**：`teamState`

**语义**：

- 横轴：高要求与责任承担，左低右高；
- 纵轴：心理安全感，下低上高；
- 最终高亮区域由 `teamState.zone` 决定；
- 当 `positionHint` 存在时，定位点落在分界线上并显示"可能是 X 区或 Y 区"；
- 当 `adjacentZone` 存在时，定位点落在主区域靠近边界的位置。

**轴向依据**：Edmondson《Teaming》第四章 Figure 4.1。

### 7.2 NetworkGraph（V2）

**位置**：Part 2 主体

**输入**：`nodes` + `edges`

**节点字段**：

| 字段 | 说明 |
|------|------|
| `name` | 发言者完整姓名 |
| `participantType` | `internal` / `external` / `facilitator` / `unknown` |
| `primaryInteractionFunction` | 主要互动功能（推动/承接/挑战/观察/未明显观察到） |
| `primaryFunctionReason` | 主要功能的判定依据 |
| `speakingShare` | 发言占比（百分比） |
| `functions` | 全部功能事件列表 |

**节点角色视觉**：`ROLE_VISUAL` 导出自 `NetworkGraph.tsx`，统一颜色映射。

**边字段**：

| 字段 | 说明 |
|------|------|
| `source` / `target` | 各为一位发言者 |
| `weight` | `strong` / `moderate` / `light` |
| `nature` | 语义描述 |
| `frequency` | 频次，决定线宽 |

**附加说明**：

- 节点旁边的百分比代表发言占比；
- 连线越粗，表示互动越频繁；
- 布局为静态扇区布局，不使用力导向动画，目的是保持 PDF 导出稳定、视觉可复现。

### 7.3 V1 图表（冻结）

`TeamStateChartV1` 与 `NetworkGraphV1` 仅用于旧报告（`schemaVersion=1`）的兼容渲染，不再接收新功能。

## 8. 交互功能

### 8.1 隐藏姓名（匿名查看）

- "匿名查看"在浏览器中用 A/B/C…替换姓名和正文姓名；
- PDF 按当前匿名状态导出；
- 代号规则：
  - 前 26 人使用 `A-Z`；
  - 超过 26 人后使用 `A1`、`B1` 这类扩展形式。

### 8.2 控件隐藏

`AnalysisDashboardV2` 支持 `hideControls`：

- 为 `true` 时，不显示返回、隐藏姓名、导出 PDF 按钮；
- 常用于飞书报告页或需要纯展示的场景。

### 8.3 返回

如果父组件传入 `onReset`，页面左上会显示"返回"按钮，用于回到上一步或列表页。

### 8.4 自定义标题

`customTitle` 用于在批量下载场景下覆盖默认标题（例如使用文件名）。

## 9. PDF 导出与匿名模式

### 9.1 导出方式

- 当前版本由浏览器端将报告转为 PDF，不上传到第三方文件服务；
- V2 使用 `src/lib/reportPdf.ts` 的 `buildReportPdf` 函数，按 `[data-pdf-page]` 分页；
- V1 旧报告继续使用 `html-to-image` + `jsPDF` 的旧导出路径（已冻结）。

### 9.2 固定三页结构

报告采用固定三页结构：

- 第 1 页：开头与 Part 1；
- 第 2 页：Part 2；
- 第 3 页：Part 3 与 Part 4。

### 9.3 版式

- PDF 使用 A4 纵向导出；
- 报告版心收窄至接近目标样稿的阅读宽度；
- 每个页面整体缩放后落在一张 PDF 页内，避免组件被截断或跨页；
- 页面视觉结构固定，不向读者暴露内部篇幅策略。

### 9.4 批量下载

- 报告汇总页提供"一键下载所有报告"：
  - 待本批分析全部结束后，将所有已完成报告（包括基础事实版）逐份按同一 PDF 组件生成；
  - 打包为一个 ZIP 下载；
  - 分析失败且没有报告内容的项目不进入压缩包。

### 9.5 文件命名

文件名格式如下：

```text
报告-{自定义标题或未命名}-{reportTimestamp}.pdf
```

时间戳中的空格、冒号、连字符会被替换为下划线，确保跨平台下载兼容。

## 10. 附录：V2 数据结构

### 10.1 AnalysisResultV2

```typescript
interface AnalysisResultV2 {
  schemaVersion: 2;
  reportTimestamp: string;
  metadata: MeetingMetadataV2;
  summary: string;
  teamState: TeamStateV2;
  behaviors: TeamBehaviorsV2;
  dialogueNetwork: DialogueNetworkV2;
  unfinishedDialogues: UnfinishedDialogueV2[];
  unseenDisagreements: UnseenDisagreementV2[];
  leaderAdvice: LeaderAdviceV2[];
}
```

### 10.2 TeamStateV2

```typescript
interface TeamStateV2 {
  zone: 'Apathy' | 'Comfort' | 'Anxiety' | 'Learning' | 'Difficult to Judge';
  adjacentZone: string | null;
  positionHint: string | null;
  boundaryDimension: 'psychologicalSafety' | 'accountability' | 'none';
  psychologicalSafety: DimensionAssessmentV2;
  accountability: DimensionAssessmentV2;
  analysis: string;
  crossBoundaryLearning: CrossBoundaryLearningV2;
}
```

### 10.3 DimensionAssessmentV2

```typescript
interface DimensionAssessmentV2 {
  direction: 'higher' | 'lower' | 'insufficient';
  evidence: string[];
  confidence: 'high' | 'medium' | 'low';
  summary: string;
  standardStrength?: string | null;
  validationMode?: string | null;
  monitoringMode?: string | null;
}
```

### 10.4 LeaderAdviceV2

```typescript
interface LeaderAdviceV2 {
  action: 'frame_for_learning' | 'create_psychological_safety' | 'learn_from_failure' | 'cross_boundaries';
  advice: string;
  reasoning: string;
  timing: string | null;
  signalToWatch: string | null;
  optionalScript: string | null;
}
```

### 10.5 DialogueNetworkV2

```typescript
interface DialogueNetworkV2 {
  nodes: NetworkNodeV2[];
  edges: NetworkEdgeV2[];
  analysis: string;
  noteworthyPattern: string | null;
}

interface NetworkNodeV2 {
  name: string;
  participantType: 'internal' | 'external' | 'facilitator' | 'unknown';
  primaryInteractionFunction: PlayerRoleV2;
  primaryFunctionReason: string;
  speakingShare: number;
  functions: { function: PlayerRoleV2; events: string[] }[];
}

interface NetworkEdgeV2 {
  source: string;
  target: string;
  weight: 'strong' | 'moderate' | 'light';
  nature: string;
  frequency: number;
}
```

### 10.6 未完形与非共识

```typescript
interface UnfinishedDialogueV2 {

  conversationSoFar: string;
  whatRemains: string;
}

interface UnseenDisagreementV2 {
  topic: string;
  differentConcerns: string;
  sharedGoal: string;
  whyItMatters: string;
```
