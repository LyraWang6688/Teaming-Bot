# 个人面试 · 材料包

> 用途：面试前 30 分钟过一遍。核心是**能被追问三层**，不是背稿。
> 口径来源：母本 §二（数字）、§三（故事）、§八（锚点）、§六（红线）。
> 🔒 **红线提醒**：不说"基于 Bion 群体动力学已落地"；不说"批量打包 ZIP"；不报初始化门禁段数；不说"从零一个人手写"；不宣称 exactly-once。

## 三、五个深挖锚点（浓缩版）

### 锚点 1｜为什么最后选官方 SDK

- **结论**：不是 SDK 更好用，而是**它是唯一能承担 token 全生命周期治理的方案**。
- **代价**：SDK 版本锁死 1.71.0；未封装的端点要自己手写；错误对象必须先脱敏才能进日志。
- **判断标准**（会被追问）：不是"新方案更好用"，而是"**旧方案有结构性缺陷**"——CLI 的凭据存在文件系统里，这不可治理。

### 锚点 2｜"报告存了但用户收不到"

- **结论**：**"数据已经成功"不等于"后续工作已经登记"**。
- **细节**：报告先独立提交 → 再登记交付任务 → 登记失败只写日志 → 入口见"已完成"直接 return，重启不补偿。
- **修复**：四阶段全部进同一事务，仓储层显式接受事务对象。
- **原则句**：判断事务边界的问题不是"谁调用谁"，而是"**哪个写入失败之后，另一个写入就失去了意义**"。

### 锚点 3｜状态机与"唯一事实来源"

- **结论**：进程内状态不能作为事实来源；**捡到过期锁就重跑，必须配合状态收敛**。
- **细节**：7 态任务 + `SKIP LOCKED` + 租约心跳；17 条僵尸任务的节奏与 20 分钟 TTL 吻合；释放租约与判断 pending 必须是一次原子更新，且**必须校验返回值**（原来更新 0 行却写了"重排成功"的日志）。
- **诚实代价**：**未实现严格 exactly-once**，也没做任意长任务的租约心跳/fencing。

### 锚点 4｜让模型取证，把判定权交回代码

- **结论**：**模型擅长取证，不擅长稳定分类**。
- **做法**：证据提取（模型）→ 判定锁定（代码）→ 报告写作（模型，禁止改判）；引用必须原文逐字可回溯，否则删证据并降级；发言者识别、占比、姓名对齐、频次合并全部由代码完成。
- **亮点句**：证据不足时输出"可能是 A 区或 B 区"，把定位点画在分界线上——**宁可不定位，也不要编造确定性**。

### 锚点 5｜授权静默失效（真实生产事故）

- **结论**：**对必然持续失败的错误重试，只是在浪费调用，并且骗自己。**
- **细节**：`refresh_token` 7 天有效、仅"有活动"时续期；两个集成掉线，恰在部署前 17 小时过期；根因是授权异常没被分类，冒泡到通用 catch 被当临时错误**重试 3 次**，最终失败且**用户无通知**，只能人工跑 SQL。
- **修复四层**：分类为阻塞且不重试 → 用与失效凭据无关的机器人通道主动通知 → 签名令牌免登录重授权 → 85 天窗口自动补发。

## 四、灵魂问题专区（**面试真正的胜负手**）

这些问题比技术问题更致命，因为它们决定面试官**信不信你前面说的**。

### Q1：「这个项目是 AI 写的吧？」

**❌ 不要说**："主要是我写的，AI 只是辅助。"（含糊，且经不起追问）
**❌ 不要说**："是 AI 写的。"（自我否定）

**✅ 推荐答案**：

> "编码环节我大量用了 AI 工具，这个我不回避。但有三件事不是 AI 主动提出的：**方案被推翻、方向被否决、验收不通过。**
>
> 举个例子：把飞书集成从 CLI 整体迁到官方 SDK 那次，删掉 2277 行、新增 2035 行，删掉的三个模块是我自己写的。AI 不会建议我'把能跑的代码删掉重写'，它只会帮我把重写的活儿干得很快。
>
> 还有那次静默失败——报告落库了但交付任务没登记成功。AI 写这段代码时会写得很规范，但它不会提醒我'你这四个写入必须在一个事务里'。因为那是**业务后果**，不是语法问题。"

### Q2：「你一个人做的？」

按真实情况回答，然后立刻界定范围：

> "产品的定义、方案选型、架构、验收标准、部署运维和全部设计文档是我负责的。我可以把哪部分是我决策的、哪部分是执行层面的，讲得很清楚。"

### Q3：「为什么用户这么少？」

**❌ 不要说**："还在推广阶段。"（空洞）
**✅ 推荐**：

> "真实跑过，但规模确实小。我在 8 月还停摆了整整一个月，一个月只有 1 次提交。9 月回来做了 49 次提交，也经历了这个项目最大的一次改造和一次验收不通过。
>
> 我现在的判断是：**它已经证明了技术链路可行，但还没证明有人真的需要它。** 这是下一步要解决的问题，不是靠多加功能能解决的。"

### Q4：「为什么没有测试？」

**✅ 直说 + 给计划**：

> "有一份验收文档里明确写着'测试（当前为 0，验收硬门槛）'。现在有 3 个测试文件、27 个用例，覆盖会议资格判定、重授权令牌、运行时开关，但计划里的故障注入用例没落地。
>
> 我的判断是：**先把不可破坏约束和事务边界写成可测的断言，再补端到端**——因为前面那些失败模式（静默丢失、状态分叉）才是真正会出事的，而不是函数返回错值。"

### Q5：「exactly-once 做到了吗？」

**✅ 明确否认**：

> "没有，我不宣称。我做的是：7 状态任务机、原子领取、租约、把幂等键落在业务目标维度（建任务时冻结 Base 目标，不回退当前活跃项目）。
>
> 但我没做任意长任务的租约心跳和 fencing，20 分钟的锁仍然是运行上限假设。**在不宣称 exactly-once 的前提下设计补偿机制**，比假装做到了更实际。"

### Q6：「你这套东西和市面上 AI 会议总结的区别是什么？」

> "它们大多数在做**摘要**：谁说了什么，重点是什么。
>
> 我做的是**判断**：这个团队现在的互动结构是什么样的。而且判定权不在模型手里——模型只负责从文字稿里取证，判定由代码锁定，写作阶段不许改判。因为**模型擅长取证，不擅长稳定分类**。
>
> 还有一条：证据不足时我不硬给结论，会输出'可能是 A 区或 B 区'，把定位点画在分界线上。"

### Q7：「如果重做一遍，你会怎么做？」

**✅ 三个具体答案**（比"我会更早写测试"高级得多）：

> "第一，**不会那么早做多账号**。我做完多集成功能没几天就自己删掉了，说明当时做早了。
>
> 第二，**第二轮方案最多给两周**。CLI 那条路从架构上就不成立，我拖了三周。
>
> 第三，**先写不可破坏约束，再写代码**。后来我把'跨表写入必须同事务''幂等键必须落在业务目标维度'这些写进规格，那次整改的效率明显高很多。"

## 五、技术追问题库（快速过）

| 问题 | 你答案的关键词 |
|---|---|
| 为什么用长连接不用 webhook？ | 事件推送型 + 服务端常驻；代价：长连接不补发离线事件，需要对账兜底 |
| 多租户怎么隔离？ | 业务函数必须显式接收 `integrationId`，禁止从 `process.env` 读用户级配置；同 `union_id` + 组织只保留一条 active |
| 敏感字段怎么存？ | 统一 AES-256-GCM 加密落库，只在服务端解密；前端只展示脱敏值。**代价：换密钥需要先设计轮换** |
| 怎么做可观测？ | 审计日志覆盖 OAuth / 刷新 / 配置 / 事件 / Base / 通知；SDK 日志出口白名单摘要 |
| 第三方 SDK 出错怎么办？ | 第三方异常是**不受控输入**，统一包装后才能进日志；用哨兵密钥做替代测试验证无泄漏 |
| 多维表格字段改名了怎么办？ | 按 `field_id` 绑定，运行时解析当前字段名，缓存 10 分钟、遇错强刷；避免硬编码中文字段名 |
| 报告怎么导出？ | 3 页 PDF，按分页容器渲染，用 html-to-image + jsPDF；批量是**逐份导出**（不说打包 ZIP） |
| 匿名模式怎么做的？ | 前台 A-Z 昵称映射，超过 26 人用 A1 形式，PDF 按当前匿名态导出 |

## 六、反问环节（准备 3 个，用 2 个）

1. "你们现在有多少条链路是**跑在人的记忆里**的？比如某个人工补偿步骤，只有某个人知道怎么做。"
2. "如果明天让 AI 接手你们一半的编码工作，你们最先会在哪一步加验收门禁？"
3. "这个岗位最怕出的那类线上问题是什么？"

> 三个问题都直接来自你的项目经验，问出来自带可信度。

## 七、收尾话术

当面试官问"你还有什么想说的"：

> "我想说一句关于 AI 的。这套系统里，AI 帮我把决定变成代码，速度很快。但今天我讲的所有教训——事务边界、状态收敛、异常分类、理论减法——**它一条都没有主动告诉我**。
>
> 所以我现在最看重的能力不是'能不能写出来'，而是**知不知道该写什么、以及出了事谁来兜**。这也是我希望在这个岗位上做的事。"
